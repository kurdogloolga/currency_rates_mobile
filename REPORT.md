# Отчёт по лабораторной работе №4: мобильное приложение

## 1. Тема и обоснование

Выбран **вариант Б**: конвертер валют из Лаб 3 перенесён на мобильную
платформу (Android) с обязательным расширением — экранами сравнения курса за
неделю и за месяц.

Почему этот вариант:

- предметная область уже знакома, поэтому время ушло на главное — новый язык,
  мобильную платформу и аналитику, а не на постановку задачи;
- показатель «курс валютной пары» естественно подходит для требований
  части 3: у него есть история, минимум, максимум, среднее, изменение и
  тенденция;
- тема не требует отдельного согласования с преподавателем.

Расширение по сравнению с Лаб 3:

| Было в Лаб 3 (веб, Blazor) | Стало в Лаб 4 (Android, Flutter) |
|---|---|
| Курс на одну дату | История за 30 дней, экраны «Неделя» и «Месяц» |
| Только конвертация | График, мин/макс с датами, среднее, изменение в единицах и %, тенденция |
| — | Кросс-курсы любой пары через MDL, популярные валюты с изменением за день |
| Кэш на сервере | Локальный кэш на устройстве, работа в режиме полёта |

## 2. Смена языка

| | Лабораторная 3 | Лабораторная 4 |
|---|---|---|
| Язык | **C#** | **Dart** |
| Платформа | .NET, Blazor (веб) | Flutter, Android |
| Тесты | xUnit (`dotnet test`) | `flutter_test` (`flutter test`) |

Язык изменён: C# → Dart. .NET MAUI не рассматривался, потому что это тот же C#.

Код Лаб 3 не переиспользовался: ни копированием, ни переводом через ИИ.
Из Лаб 3 взят только внешний **источник данных** (публичный XML НБМ) — это
сервис, а не код. Логика написана заново и устроена иначе:

- в Лаб 3 курсы получал сервер и искал предыдущую дату при пустой публикации
  (окно 14 дней); в Лаб 4 приложение само загружает ряд дат и кэширует каждый
  день отдельно;
- в Лаб 3 действовало правило «кэш применяется только после явного
  подтверждения»; в Лаб 4 кэш показывается сразу, с плашкой о дате
  актуальности (так требует лабораторная);
- статистики периода, кросс-курсов и графиков в Лаб 3 не было вовсе.

## 3. Источник исторических данных и его ограничения

**Источник:** официальный XML Национального банка Молдовы,
`https://www.bnm.md/ru/official_exchange_rates?get_xml=1&date=ДД.ММ.ГГГГ`.
Ключ API не нужен.

**Подход — комбинация:** множественные запросы по датам и накопление в
локальной базе.

1. При первом запуске загружаются 30 календарных дней: по одному запросу на
   дату, до 6 запросов параллельно, сначала самые свежие.
2. Каждый день сохраняется в локальный кэш (`SharedPreferences`, JSON
   `дата → курсы`). Курсы прошедших дат не меняются, поэтому повторно они не
   запрашиваются.
3. При каждом следующем запуске запрашивается только сегодняшний день: это
   и обновление, и проверка связи. Если сети нет, используются сохранённые
   данные, а на экране видна их дата.
4. Записи старше 60 дней удаляются.

Поэтому месячный график доступен **сразу после установки**, а не через месяц
накопления: история берётся у НБМ, а не копится с момента установки.

**Проверенное поведение источника (19.11.2026):**

- НБМ публикует курс на **каждый календарный день**, включая выходные;
- курс на завтра публикуется заранее (запрос на 20.11 вернул данные уже 19.11);
- для будущей даты без публикации возвращается **HTTP 404 с пустым телом** —
  это трактуется как «не опубликовано», а не как ошибка;
- в ответе 40 валют, все к MDL; курс MDL к MDL = 1 добавляется приложением.

**Ограничения:**

| Ограничение | Следствие и как учтено |
|---|---|
| Нет запроса «за период», только за одну дату | Первый запуск — 30 HTTP-запросов (несколько секунд). Потом — 1 запрос за запуск благодаря кэшу |
| Первый запуск без сети | Данных нет нигде, показывается экран «Курсы недоступны» с кнопкой «Повторить» |
| Обрыв связи во время загрузки | Сначала грузятся свежие даты, поэтому сегодняшний курс уже получен; после первой сетевой ошибки остальные даты не перебираются; пропуски видны («Данные есть за N из M дней») |
| Дата определяется по часам устройства | Для пользователя в Молдове совпадает с `Europe/Chisinau`; при другой зоне период может сдвинуться на день |
| Нет CORS-заголовков | Веб-версия работает только в Chrome с `--disable-web-security`. На целевой платформе Android ограничения нет |
| Кросс-курсы (EUR/USD и т.п.) | Рассчитываются через MDL (`EUR→MDL / USD→MDL`), это не котировка межбанковского рынка |
| Качество названий в XML | Встречаются разный регистр и латинская «p» вместо «р» («доллаp», «pупия»). В интерфейсе используется собственный справочник русских названий, название из XML — запасной вариант |

**Порог «без изменений».** Тенденция «без изменений» ставится, если
|изменение| < 0,01 %. Сравнивать с нулём «в лоб» нельзя: кросс-курсы
получаются делением, и шум округления давал бы ложный «рост» или «падение».
При EUR ≈ 20 MDL порог 0,01 % равен 0,002 MDL — меньше шага публикации НБМ
(0,0001 × 20).

## 5. Что ИИ сгенерировал корректно, а где ошибся

### Корректно с первого раза

- **Слой данных.** Парсер XML, HTTP-клиент с классификацией ошибок, кэш и
  репозиторий. Тесты парсера (19), клиента (12), кэша (3) и репозитория (8)
  прошли при первом запуске.
- **Статистика и валидация.** 32 теста прошли с первого запуска. Сразу учтены
  неочевидные случаи: пустой набор возвращает `null` вместо деления на ноль,
  одна точка даёт изменение 0, точки сортируются независимо от порядка во
  входе, отвергаются `NaN`, `1e5`, запятая в XML.
- **Проверка источника до написания кода.** ИИ сначала сделал реальные
  запросы к НБМ (выходной, будущая дата) и обнаружил, что выходные
  публикуются, а будущая дата отдаёт 404. От этого зависела вся стратегия
  истории.
- **Качество данных.** ИИ заметил латинские буквы в русских названиях валют
  НБМ и сделал собственный справочник.

**визуальной части** (переполнения, обрезка, тексты) и в **окружении**
(генераторы проекта, CORS, тяжёлые инструменты). Их не видно в коде, они
находятся только при запуске: скриншотами и виджет-тестами.

## 6. Насколько сложнее или проще было работать с ИИ на новом языке

Dart и Flutter для меня новые; Лаб 3 написана на C#, с которым я знакома
лучше. Главное наблюдение: **писать на новом языке с ИИ оказалось проще, чем
ожидалось, а проверять написанное — заметно сложнее, чем на знакомом языке.**

**Что стало проще.**

- *Порог входа почти исчез.* Синтаксис Dart (null-safety, `switch`-выражения,
  records `(String, String)`, `case final rate?` в коллекциях, `enum` с полями),
  устройство Flutter (виджеты, `ChangeNotifier`, `ListenableBuilder`) и
  библиотеки (`fl_chart`, `shared_preferences`) не пришлось изучать заранее.
  ИИ сразу использовал идиоматичные конструкции, и разбираться можно было
  по ходу, на работающем коде.
- *Перенос идей, а не кода.* Задача из Лаб 3 знакома, поэтому я могла
  формулировать требования на уровне поведения («пустой ответ — не ошибка
  выходного дня», «кэш показывать с датой»), не зная, как это пишется на Dart.
  Правило «не переиспользовать код Лаб 3» в этом смысле помогло: ИИ строил
  решение заново под мобильную платформу, а не транслировал C#.
- *Тесты как переводчик.* Тесты описывают ожидаемое поведение почти обычным
  языком (`'пустой набор — null, без исключений'`). По ним проще убедиться, что
  код делает нужное, чем читая незнакомый синтаксис.

**Что стало сложнее.**

- *Труднее заметить ошибку при чтении.* На C# я бы сразу увидела, например,
  отсутствие `Flexible` в строке или неправильный порядок загрузки. На Dart
  такие места выглядят правдоподобно, и без запуска их не видно. Почти все
  ошибки из раздела 5 нашлись не при чтении кода, а по скриншотам и
  виджет-тестам.
- *Незнакомая экосистема.* Генератор `flutter create` перезаписывает файлы,
  веб-сборка упирается в CORS, `dart format` меняет десятки файлов. Это не
  ошибки языка, но без опыта не понятно, нормально ли то, что происходит, и
  приходится больше доверять объяснениям ИИ.
- *Защита требует понимания каждой строки.* Писать на Dart с ИИ быстро, но
  объяснить фрагмент на защите — отдельная работа: разобраться в
  `LayoutBuilder`, `IndexedStack`, `Future.wait` пришлось после генерации.

**Итог.** ИИ заметно снижает стоимость смены языка на этапе *написания*, но
не на этапе *проверки*. На знакомом языке я контролирую ИИ чтением кода; на
новом — в основном через поведение: тесты, анализатор, запуск и скриншоты.
Поэтому на новом языке тесты и автоматические проверки важнее, чем на
знакомом, и в этой работе они появлялись вместе с кодом на каждом этапе, а не
в конце. Навык работы с ИИ действительно не привязан к языку: постановка задачи
по этапам, требование тестов, проверка результата запуском одинаково
работают и в C#, и в Dart. А вот навык *проверки* сгенерированного кода
приходится нарабатывать заново для каждого языка.

## 8. Демонстрация

```bash
flutter pub get
flutter run        # устройство Android или эмулятор
```

Сценарий проверки офлайн-режима:

1. Запустить приложение с интернетом, дождаться загрузки (данные сохраняются).
2. Включить режим полёта и перезапустить приложение. Курсы на месте, жёлтая
   плашка «Нет связи · сохранённый курс на ДД.ММ.ГГГГ» и карточка «Работа без
   сети» с временем последнего обновления.
3. Экраны «Неделя» и «Месяц» работают на сохранённых данных.
4. Для проверки первого запуска без сети: очистить данные приложения и
   запустить в режиме полёта. Появится экран «Курсы недоступны» с кнопкой
   «Повторить», без аварийного завершения.
